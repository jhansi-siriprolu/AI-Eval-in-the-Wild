Will it fit in 8GB? Find out live.

Every parameter in a model is a number that has to sit in memory. Quantization shrinks how many bits each number uses. Drag the sliders below and watch the math.

The formula

weight_bytes  = params × (bits / 8)
kv_cache_bytes ≈ 2 × layers × ctx_tokens × hidden_dim × (bits_kv / 8)   (grows with context length)
runtime_overhead ≈ macOS + Python + MLX graph buffers, roughly 600 MB–1 GB fixed

total ≈ weight_bytes + kv_cache_bytes + runtime_overhead

This calculator uses simplified, representative constants (not a specific model's exact architecture) so you can build intuition. Real numbers vary ±20% by model architecture.

This is exactly why the course model is Qwen2.5-1.5B-Instruct-4bit — at 4-bit, a 1.5B model needs well under 1GB of weights, leaving the rest of your 8GB for macOS, your browser, and the KV cache.

The trade-off you're accepting

Lower bit-width means each weight is a coarser approximation of the original trained value. In practice, 4-bit quantization of modern models costs roughly 1–3% accuracy on benchmarks like MMLU compared to fp16 — a small, well-studied cost for a 4x memory saving. You'll measure this gap yourself once you run real evals in Lesson 08.
